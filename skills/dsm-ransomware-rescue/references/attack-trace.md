# 从保存的日志和内存还原入口

适用时机：易失密钥与现场已先行保全，需要回答入侵路径、漏洞或执行顺序。不要为等待归因而延误 RAM 采集。证据记录和原始载荷分开保存，公开摘要与偏移即可，不发布原始请求、完整执行命令或业务日志。

## 先建立可复核的输入

对每份材料记录原归档/成员、原 SHA、派生 SHA、转换步骤和验证等级。日志行号从 1 开始，并说明按什么字节分隔；RAM 偏移是文件偏移，不自动等于 GPA 或 VA。XZ 完整解压且 CRC 通过可验证压缩流；可读文本不等于整个文件正确。加密 footer 后的追加区可能保存攻击后事件，要单独列为原始追加内容。

用 `scan_indicators.py` 搜索已保存材料，将输出放入私有目录；有截断标记就不能宣称扫描结果完整。用 `carve_memory.py` 保全相关窗口和源摘要。典型检索方向为 plugin delimiter、`LD_DEBUG_OUTPUT`、具体 cron 文件名、样本路径、编码命令片段，而不是只搜勒索家族名。网页和研究资料只提出假设，最后以本机材料核对。

## 从“附近有字符串”提升到关联证据

先找时间、PID、服务和记录边界；重复缓冲副本不计为多个事件。本案先用解密 auth.log 与 RAM 中同一整行做字节比对，再检查含恶意输入的另一条残留日志记录。

`.SDATA.journald` 字样不自动证明取得了完整 journal。若布局与 syslog-ng NVTable 相符，检查表头、索引、条目长度和 NUL 边界，确认 MESSAGE、PID、时间字段由同一索引表指向。参考[原始结构定义](https://raw.githubusercontent.com/syslog-ng/syslog-ng/syslog-ng-3.37.1/lib/logmsg/nvtable.h)；不能把参考源码版本当作受灾软件版本。

物理相邻页不必虚拟相邻。逻辑对象跨页时，需要真实页表映射才能拼接；只验证了同页字段，就明确限制到这些字段。残留/已释放对象即使结构一致，也没有日志认证和可信时间戳的保证。

## 别漏掉压缩与 NUL 分隔内容

普通 `strings` 或固定字符串阴性不排除相关内容：参数常以 NUL 分隔，脚本地址可能编码，RAM 中也可能有压缩页。本案在有限命中窗口中用可信 `lzo1x_decompress_safe` 找到候选块，严格要求完整输入消耗、返回 0、输出上限及长度 4096 字节，保存压缩起点/长度/摘要和输出摘要。

这种候选解压不自带内容认证；未重建压缩存储元数据时，不能声称已映射到某个 zram 槽、文件或进程。只恢复出编码字符串的后缀，就按后缀记录，不补齐缺失字节冒充原文。完整的有界解码内容也仅作为数据处理，不执行、导入 shell 或访问其中的网址。

## 分开写观察与推断

- `rm -f` 参数日志证明记录了删除命令，不自动证明目标存在、删除成功或由哪个父进程发起。
- `STATUS=fail` / PAM 失败不排除失败登录后的插件处理被利用；同样，普通 `LD_PRELOAD` 常量不证明攻击。
- 下载地址不是攻击发起地址；NAT 网关也不是攻击者身份。先证明原始来源的传递方式，再归因。
- 服务崩溃可能是加密共享库的后果，不能倒推为漏洞触发点。扫描命中不等于利用成功，事后扫描不等于最初入口。
- 版本标记、公开漏洞机制、输入和执行线索相符可支持高置信假设；缺少原请求、脚本或 exec 链时保留缺口，不升级为端到端证明。

交付一份时间线和证据索引：每条观察指向来源摘要、偏移/行号，单列推断、阴性搜索范围和下一份最有价值的缺失材料。新增派生物另建封存检查点，保留原分析脚本和退出码。脱敏后才更新公共记录；不把恢复钥匙或入侵载荷加入工具仓库。
