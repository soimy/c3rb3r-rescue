# 静态逆向、密钥与副本解密

## 从样本到函数

先核对原始样本摘要。对独立副本使用可信 UPX 解包，保存工具版本、完整命令、原/派生文件摘要和大小。`unpack_upx.py` 必须显式提供可信工具的绝对路径；它只运行解包工具，不运行 ELF。不要对不可信样本使用可能执行程序的加载器或 `ldd`。

本案 packed SHA 为 `802ac85d19dc6db2b1849bb3499877280544d04a0ae94d4c408b6c321669903d`，462312 字节；派生 ELF SHA 为 `78d06b74827429f8b9947ac5940b15fb6e6f724386dcb04dc6f7eb6dcd41d3a4`，1319024 字节。ELF64 x86-64、非 PIE、静态链接、stripped。RX/R 与 RW 段的 file-offset 到 VA 换算不同，不能用统一偏移换算所有数据。

REA/Ghidra 静态流程：打开派生文件 → 查字符串和调用引用 → 反编译初始化、全局 getter、文件段处理、footer 写入函数 → 用反汇编校对轮数、偏移和整数运算 → 导出证据及分析 snapshot → 关闭分析目标。保留工具版本、provider、输入摘要和函数地址。只看到密码学常量不等于确定完整算法。

本案关键地址：ChaCha key setup `0x406213`、IV setup `0x406628`、process bytes `0x4066ee`；AES-CBC `0x402945`；文件上下文初始化 `0x4232e0`；AES 记录构造 `0x4235a2`；footer writer 反编译入口 `0x42378f`（静态标注邻近 `0x423790`）。主材料全局指针 `0x5427f8`，运行模式 `0x53fc8c`。地址仅对这个派生 ELF 有意义。

## 已验证格式

数据流为 ChaCha8：32 字节 key、8 字节 nonce、64 位 counter；不是 IETF 的 12 字节 nonce 布局。每次调用最多 5 MiB，末尾不足 64 字节的调用仍消耗整块，剩余 keystream 丢弃。未加密间隙不推进 cipher counter。

末尾总长 588 字节：

| 相对尾记录起点 | 长度 | 意义 |
|---|---:|---|
| 0 | 48 | AES-256-CBC 包裹的文件 key/nonce 记录，无 padding |
| 48 | 524 | 公钥包裹记录及标记区；本方案不依赖 RSA 私钥 |
| 568 | 4 | 本会话标记；不是全家族固定 magic |
| 572 | 1 | 文件处理模式 |
| 573 | 1 | 分段参数 |
| 574 | 1 | crypto 模式，当前只接受 0x20 |
| 575 | 1 | 保留字节 0 |
| 576 | 4 | 保留的样本字段，本解密器不用于推断攻击者身份 |
| 580 | 8 | little-endian 原文件大小 |

内存主材料为 `IV16 + AES-key32`。解开 48 字节得到 `file-key32 + nonce8 + nonce8`。重复 nonce 是候选过滤条件，**不是认证**：错误 IV 可能只破坏前一块 key，而重复 nonce 仍相同。必须验证整个文件。

运行模式 0x21 写入的是诱饵随机材料；不能套用 0x20 流程。文件模式 0x24 为全文件、0x26 为前 1 MiB、0x25 为分段；分段参数不等于简单的百分比长度，整数运算和 3/5 段选择以脚本与反编译对照为准。

## 内存候选与检验

`recover_ram_keys.py --ram SAVED_RAM --profile REVIEWED_PROFILE --output NEW_PRIVATE_DIR` 从只读映射中提取候选，不打印 key 字节。除全局主材料外，ChaCha state 的 key/nonce 与相邻原始字段重复，可用于发现文件对象；它们可能是过期内存，尚需关联文件描述符、路径和 footer。

对于 `capture_process_memory.py` 产生的进程映射集合，使用 `recover_process_key.py`，按保存的 VA 直接读取，不走 QEMU 页表或 PCI hole 换算。它核对样本摘要、代码签名、0x20 模式、每个所需映射的 SHA 和不可读页，才保存 48 字节候选。候选仍须经已知原文或完整历史摘要验证；采集集合也不包括寄存器或未映射/已释放物理页。

先验证公开 ChaCha8 向量、计数器进位、短块丢弃和分段边界，再做多个真实正反文件对照。至少包含全文件、首段和分段样本。比较完整 SHA-256 或逐字节内容；不能只判断 tar magic、图片可预览或文本“看起来合理”。

本案五组真实样本全部逐字节一致；恢复日志中的 23 份 XZ 完整读到 EOF 并通过 CRC。一个文本日志存在非 UTF-8 字节，因此保留不确定状态；三个文件在 footer 之后还有新增日志，追加部分单独保全。

重复 footer 不意味着按顺序解密两次即可。10/22 大备份出现两组 key 交错影响不同区域，候选数据库在中间区域仍不确定；不能自动截掉 588 字节、伪造成功收据或把部分 gzip 输出导入数据库。

脚本当前只处理 EOF 完整、尺寸一致、已验证标记与 0x20 模式，失败时不覆盖输入；新增输出校验失败会移除。本次真实密钥保存在私有目录，仓库和合成测试都不包含它。

公开向量来源：[Botan ChaCha vectors](https://github.com/randombit/botan/blob/master/src/tests/data/stream/chacha.vec)。逆向算法与布局的证据来自本地样本、反编译和真实明密文对照。
