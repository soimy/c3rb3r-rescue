# 现场保全与内存

内存是本案恢复密钥的关键证据。完成最小止损后，优先采集已经可用的易失状态；全盘盘点和归因可以在其后展开。PVE 路径已用于本次事件；物理 Linux / DSM 使用[另行说明的采集流程](physical-memory_CN.md)，不要照抄 VM 的文件偏移映射。

## 暂停与远程访问

先确认进程可执行映射、命令行、启动时间和线程状态。对于已明确的加密进程，SIGSTOP 可保留进程状态；它不清除后门，也不能保证其他进程或内核 I/O 停止。`D` 表示不可中断等待，STOP 可能待稍后才生效；本案最终看到 `T` 和稳定 CPU 时间才记录为暂停。

将 `/proc/PID/exe` 保全到新文件，可取回磁盘上已删除但仍被进程引用的样本。记录原路径、删除状态、字节数、SHA-256、采集时间；不要执行它。记录文件描述符、maps、线程和父进程关系，输出可能包含敏感文件名。

同步服务也可能把密文覆盖到其他副本。确认身份后暂停相关 Cloud Sync/Drive 进程，并核对状态。客户端暂时无法断开时，阻断共享访问只是局部措施，随后仍需收紧来宾全部网络。不要因发现一个客户端有连接就将其判为感染源。

保留 PVE 控制台。查看真实 SSH_CONNECTION，识别 NAT、ZeroTier、网关与来宾网卡。根据现有链路设计临时规则，先准备可执行回退，限制到准确的接口、协议和连接元组。规则必须同时覆盖进入、离开和宿主访问来宾的路径；不能假定同桥流量会经过路由器转发链。

本案 DHCP 租约后来失效，DSM 退回链路本地地址；经控制台添加临时管理地址才恢复取证 SSH。保留规则不等于保留地址，不能为解决租约问题直接开放全部网络。操作前后保存规则与计数器，保留准确的规则句柄/表名用于后续撤销。

## QEMU RAM 采集

先保存 VM 配置、QEMU PID、启动 ticks、maps、RAMBlock/内存区域映射及磁盘直通情况。一个大的匿名映射不自动等于 guest RAM，必须和 QEMU 内存布局对应。本案采集了一个 16 GiB `pc.ram` 映射，持续约 90 秒，来宾未暂停，所以**不是单时点一致快照**。

`capture_qemu_ram.py` 接受显式的 `--pid --expected-start-ticks --start --length --output`。它验证进程身份、精确映射、可用空间、完成后的映射/身份和输出读回摘要；不探测其他进程，不发信号，不附加调试器。所有参数应来自当前读到的真实状态，不能套用旧 PID、地址或 VMID。

采集文件和收据保存到宿主私有持久存储。错误或短读会留下未完成副本，缺少成功收据的文件不能作为完整采集。本案原采集脚本、范围和摘要保存在私有封存区；新工具是对已用方法的参数化整理，不冒充当时运行的原文件。

## 页表与物理地址

本案 QEMU 文件偏移 0..3 GiB 对应低端物理内存；后续偏移映射到 4 GiB 起始物理内存，中间有 PCI hole。直接把文件偏移当物理地址会错读页表。此布局必须按 VM 核实，不能推断所有 PVE 来宾都一样。

从已知 ELF 代码签名定位物理页，再反查 user/present、可执行 PTE 和非大页 PDE。沿候选 PD 翻译静态全局地址，核对代码签名、运行时模式、主材料指针与长度。当前工具只支持本案低 1 GiB 进程虚拟地址、4 KiB user pages；遇到 huge pages 或其他布局应拒绝并重新实现，不猜测。

候选页表可能已经过时；正确的页表翻译只是候选定位。最终必须解开真实文件尾记录并用独立已知原文或完整校验确认。

## 内存也可能保留入口证据

磁盘日志缺少匹配项时，已保存 RAM 中可能留有 journald/syslog 缓冲、插件参数或已释放消息。本案从 RAM 找到带完整 delimiter/LD_* 注入和 cron 路径的登录处理消息，随后与独立 rm 日志的时间和文件名对应。仅找到库中的 `LD_PRELOAD` 常量完全不够。

先用 `scan_indicators.py` 生成私有上下文，再用 `carve_memory.py` 保存精确范围，分清文件偏移、GPA 和 VA。保全源 SHA 与片段 SHA；标记截断、重复和损坏。Base64 只解码为文本文件，不 eval、不管道给 shell、不访问其中的地址。消息附近时间字段的关联要说明边界，未经完整结构解析不能冒充已验证的原始 journal 事件。

## 逻辑封存

`seal_evidence.py copy SOURCE NEW_DEST` 只针对已稳定的证据树。源文件元数据变化、读回不一致或目的已存在即失败。符号链接和特殊文件只记录元数据，不追随；普通文件复制为独立 inode，逐个读回后设为 0400，目录设为 0500。

`seal_evidence.py verify SEALED_DIR` 验证清单自身和清单列出的每个文件。清单摘要要另存一个可信位置。只读权限不是硬件写保护、WORM、可信时间戳或签名；源目录在遍历前发生的变化和原始系统被篡改的可能性也不由该工具消除。完整物理取证另需磁盘镜像、写保护和空间计划。
