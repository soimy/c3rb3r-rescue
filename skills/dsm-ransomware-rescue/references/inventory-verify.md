# 文件梳理、复制与验证

`inventory.py` 统计目录元数据，不读取文件正文。根目录、显式挂载、Btrfs 子卷和 Docker 子卷需分别核实：Btrfs 的 st_dev 不同会让一次 `-xdev` 或同设备扫描漏掉共享目录。每次扫描报告被跳过的设备、错误、未完成组和扫描根；不能因为进程退出 0 就声称已经覆盖整个 NAS。

列出 mountinfo、实际卷与子卷后，人工构造互不重叠的补扫根列表，NUL 分隔，避免中文、空格或换行路径破坏命令。`verify_roots.py ROOTS.nul --expected-count N` 检查列表、路径、符号链接、挂载来源和重叠；必要的额外根用 `--special-root`，经确认的同源挂载祖先用 `--allow-mount-ancestor`。N 必须来自当前列表，而不是照抄本案的 25。

`.L0CK3D` 数量是疑似受影响路径数；没有后缀的文件也可能正在加密、部分覆盖或损坏。硬链接按 `(st_dev, st_ino)` 去重，同时保留全部别名；CoW 和逻辑大小不能简单换算物理占用。Docker 的 Btrfs 快照不是业务数据的有效事前备份。

复制前核对源身份、目标挂载和剩余空间；NAS 挂载丢失时不得回落到同名本地目录。密文、明文和证据收据分开。传输续传必须绑定同一份目录清单和源身份，检查 size、mtime、ctime、inode；块摘要不能替代最终完整 SHA-256。读回目的文件再校验，不能只给刚写出的缓冲区算摘要。

本案 root 导出器使用私有 Unix socket 和固定源范围，由管理员在自己的终端 sudo 启动，不开放网络服务；完成后关闭并移除 socket。那些部署参数固定的原脚本全部保存在私有原始记录中，不作为可直接在其他机器执行的默认配置。

## 结果等级

| 等级 | 可以说明什么 | 不能说明什么 |
|---|---|---|
| 历史 SHA 完全一致 | 恢复字节与保全的历史摘要一致 | 历史来源未被篡改、系统已清洁 |
| 完整归档/压缩检查 | 成员可读、长度与 CRC/校验和通过 | 跨组件时间点一致、所有业务可用 |
| 语法或文件头 | JSON 可解析、PGDMP 等头存在 | 后续内容完整、数据库可恢复 |
| 应用验收 | 具体检查和操作在恢复实例成功 | 未测试功能、生产容量或整盘健康 |
| 失败/未决 | 保留密文和候选用于后续研究 | 不能计为恢复成功 |

`verify_backup.py` 不把归档路径写入磁盘，不追随链接，不执行 SQL、配置或包内程序。TAR 遍历成员并检查尾部，gzip 读到 EOF 以触发 CRC/长度检查；Git bundle 核对 PACK 尾摘要；LFS 支持完整 64 位 OID 与 2/2/60 目录布局，逐对象比对 SHA-256。

PACK 校验不是 Git fsck。PGDMP 头不是 pg_restore 验证。文件名包含 backup 不等于包含 repositories/LFS；必须读 backup_information 的 skipped 和实际成员。检查器日志范围可能是 ID，不是数量；本案附件日志 1..55 对应 54 条源记录，artifacts 最后 ID 1034 对应 658 条源记录。

不要用 `python -O` 跳过自检断言；真实运行依靠异常和退出码，最终仍检查具体结果字段。归档中遇到未知或危险路径仅记录，不为了“修复”而改变密文或原始归档。
